# ZCode 子智能体文档

> 来源：https://zcode.z.ai/cn/docs/subagents

## 核心功能

子智能体是给 Agent 准备的专门角色。可以把 code review、测试排查、发版说明、UI 检查这类固定职责做成子智能体，让当前 Agent 在需要时调用更聚焦的角色处理任务。

## 触发方式

子智能体有两种进入任务的方式：

1. **自动委派（主要方式）**：主 Agent 在执行任务时按需自动派发子智能体。例如需要大范围检索代码库或开展调研时，主 Agent 会通过内置的 Agent 工具启动只读的 **Explore** 研究子智能体——独立上下文、并行执行、结果汇总回传，全程无需手动操作，任务流中会以工具卡片实时展示其进度。

2. **在提示词中指明角色**：把角色和任务直接写进对话，主 Agent 会按对应子智能体的定义来执行这部分工作。适合交给子智能体的任务通常职责明确，例如：

```
让 zcode-reviewer 检查当前改动有没有回归风险
```

```
让 zcode-test-helper 帮我定位这个测试为什么失败
```

> **提示**：每个子智能体的「描述」字段会直接影响自动委派的判断——把"什么时候该用它"写清楚，主 Agent 才能在合适的时机选中它。

子智能体适合处理一个明确角色下的工作；如果只是保存一句快捷提示词，用 Command 更轻；如果是可复用的方法论和素材包，用 Skill 更合适。

## 配置子智能体

子智能体通过 Markdown 文件定义。把角色文件放到对应目录后，ZCode 会自动读取：

- **用户级**（所有工作区可用，桌面端）：`~/.zcode/cli/agents/`
- **工作区级**（仅当前项目可用）：`/.zcode/cli/agents/`

每个子智能体是一个 `.md` 文件，由可选的 YAML frontmatter 和正文系统提示词组成。frontmatter 支持以下字段：

- **name（名称）**：3–50 个字符，仅限字母、数字和连字符，例如 `zcode-reviewer`。
- **description（描述）**：写清楚什么时候应该调用它——这个字段会直接影响自动委派的判断。
- **color（标识色，可选）**：子智能体在界面中的标识颜色，例如 `#3b82f6`。
- **model（模型，可选）**：为该子智能体单独指定使用的模型；留空则跟随当前会话模型。
- **tools（工具，可选）**：限定该子智能体可使用的工具范围。

frontmatter 之后的正文即该子智能体的 **系统提示词**，用于定义它的职责、检查重点和输出方式。

```markdown
---
name: zcode-reviewer
description: 在提交前检查改动是否存在回归风险
color: "#3b82f6"
model: glm-5.2
tools: Read, Grep, Bash
---
你是一个专注代码评审的子智能体，重点检查回归风险、边界条件和测试覆盖……
```

> 除了自己创建，子智能体也可以**随插件一起提供**。启用包含子智能体的插件后，对应角色会自动出现在可用列表中（来源标记为插件），无需手动放置文件。

## 角色建议

建议先为团队准备三到五个常用角色，例如代码评审、测试排查、文档整理、UI 检查和发布说明。角色数量不必太多，重点是职责清晰、触发条件明确。
